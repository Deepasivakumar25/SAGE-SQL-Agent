# SAGE — SQL Analysis & Generation Engine

SAGE is an AI-powered SQL agent that allows users to interact with a PostgreSQL database using natural-language questions.

Instead of manually writing SQL queries, users can ask questions in plain English. SAGE uses a large language model to generate SQL, validates the query for safety, executes it against PostgreSQL, handles SQL execution errors through a retry workflow, and generates a clear natural-language answer.

## Project Overview

SAGE demonstrates how LangGraph can be used to build a structured, stateful AI workflow for database interaction.

The agent follows this workflow:

```text
User Question
     |
     v
Generate SQL
     |
     v
Validate SQL
     |
     +--------------------+
     |                    |
   Valid                Invalid
     |                    |
     v                    v
Execute SQL              END
     |
     +--------------------+
     |                    |
  Success               SQL Error
     |                    |
     v                    v
Generate Answer      Retry SQL Generation
     |                    |
     v                    +----> Validate SQL
    END
```

## How It Works

### 1. Generate SQL

The user provides a question in natural language, such as:

```text
Show me employees whose salary is greater than 80000.
```

The LLM converts the question into PostgreSQL SQL:

```sql
SELECT * FROM employees WHERE salary > 80000;
```

### 2. Validate SQL

Before executing the generated SQL, SAGE checks whether the query is allowed.

Only SELECT queries are permitted.

For example:

```sql
SELECT * FROM employees WHERE salary > 80000;
```

is allowed.

A query such as:

```sql
DELETE FROM employees WHERE salary > 80000;
```

is rejected before it reaches the database.

### 3. Execute SQL

If the query passes validation, SAGE executes it against the PostgreSQL database.

### 4. Handle SQL Errors

If the generated SQL contains an error, the error is captured and passed back to the SQL generation step.

The LLM receives the previous SQL error and attempts to generate a corrected query.

The workflow can retry SQL generation up to a configured retry limit.

### 5. Generate the Final Answer

After successful execution, the database result is passed to the LLM.

The LLM converts the database result into a simple natural-language response that is easier for the user to understand.

## LangGraph Workflow

SAGE uses the following LangGraph nodes:

```text
generate_sql
      |
      v
validate_sql
      |
      +---- invalid ----> END
      |
    valid
      |
      v
execute_query
      |
      +---- success ----> generate_answer ----> END
      |
    SQL error
      |
      v
  retry available?
      |
      +---- yes ----> generate_sql
      |
      +---- no -----> END
```

The workflow uses conditional edges at two important points.

### Validation Routing

After SQL validation:

- Valid SELECT query -> `execute_query`
- Invalid query -> `END`

### Execution Routing

After SQL execution:

- Successful execution -> `generate_answer`
- SQL error with retries available -> `generate_sql`
- SQL error after the retry limit -> `END`

## State Management

The LangGraph state contains information required throughout the workflow:

- `question` - User's natural-language question
- `sql_query` - SQL generated by the LLM
- `sql_result` - Result returned by PostgreSQL
- `is_valid` - Indicates whether the SQL passed validation
- `error` - SQL validation or execution error
- `status` - Current workflow status
- `answer` - Final natural-language answer
- `retry_count` - Number of SQL generation retries


## SQL Safety

Database safety is an important part of the SAGE workflow.

The current implementation allows only SELECT queries to reach the database.

The following operations are rejected:

- DELETE
- UPDATE
- INSERT

For example, if the user asks:

```text
Delete employees who have a salary greater than 80000.
```

and the LLM generates:

```sql
DELETE FROM employees WHERE salary > 80000;
```

SAGE rejects the query during validation. The query is not executed against PostgreSQL.

This design provides a basic safety layer for read-only database interaction.

## Retry Mechanism

SQL generation can sometimes produce an invalid query. SAGE handles this through a retry workflow.

Example flow:

```text
Generate SQL
     |
     v
Validate SQL
     |
     v
Execute SQL
     |
     |
     +---- SQL Error
              |
              v
        Generate corrected SQL
              |
              v
        Validate SQL
              |
              v
        Execute SQL
```

The retry count is tracked in the LangGraph state so that the agent does not retry indefinitely.

## Security Notes

- Never commit API keys or passwords to the repository.
- Store secrets in environment variables.
- Keep `.env` in `.gitignore`.
- Use a database user with only the permissions required by the application.
- The current workflow is designed for read-only SQL execution through SELECT-only validation.
- SQL validation should not be considered a complete database security mechanism. Database-level permissions should also be configured appropriately.
